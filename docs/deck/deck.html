Tollgate

The one gate every AI agent action passes.

A control layer that checks what an AI action would really do in the company's systems, before it runs.

HackYeah 2026 AI Control Layer challenge Runs fully local on Ollama

Demo company: Nordwind Finance Center, an accounts payable team with an AI agent that pays invoices, sends email and queries the finance database.

Waiting for a person held

  • Pay 2,350.00 EUR to Krakow Logistics S.A. for invoice INV-7003-R.

  • We paid this supplier the same amount a few days ago. It looks like the same bill sent twice, so a person checks.

The problem

AI agents now act. Text filters cannot see what an action really does.

  • Agents hold real power. They pay invoices, send email, run SQL, open files and call MCP tools.

  • The words can lie. An invoice can carry a hidden instruction, a "new" bank account or fake urgency from "the CEO".

  • The danger is in the effect. "Pay INV-7001" looks harmless. What matters is which account the money goes to.

  • Agents are non-deterministic. Loops, runaway spend and wrong guesses happen without any attacker.

Judge the effect, not the prompt

Each action is resolved against the company's own records: the real invoice, the account on file and past payments.

Rules decide, AI only tightens

Fixed rules decide everything knowable in about 1 ms. AI is asked only where meaning matters, and it can only turn "allow" into "ask" or "block".

Everything is configuration

Policy, per-tool contracts and the attack feed are files. They are checked before they load, signed where it matters, and live within half a second.

Three outcomes

  • AllowIt matches the records and the rules.

  • Ask a personUnclear, over a limit, or irreversible and unproven.

  • BlockKnown bad, wrong account, or not allowed for this person.

  • Fails closed. If the AI judge errors or times out, the action waits for a person.

  • Strictest finding wins: allow < ask a person < block. One block anywhere stops the action.

  • Runs with verified values. The payment uses the amount and account on file, re-checked inside one database transaction, so there is no gap between check and use.

Quality of the guardrails Robustness and quality of guardrails 30% of the score

Ten controls. Rules first, AI where meaning matters.

Effect contracts rule

Per tool, in YAML: invoice exists, supplier on file, exact amount, account on file, not paid, duplicates and limits.

AI judge quotes the user AI

It must quote the user's own words, and the quote is checked character for character. No quote, no payment.

Data guard rule

Parses SQL, scopes rows and columns per role, masks IBANs and IDs, and caps bulk reads.

Prompt injection cascade AI

Rules first, then qwen3:0.6b screens unclear text and a bigger model confirms. The hidden sentence is removed.

Secrets detector rule

12 patterns (cloud keys, tokens, private keys) are blocked in messages and redacted in results.

Identity and delegation rule

Signed agent tokens (HMAC-SHA256). A helper agent can only get narrower rights.

Known-bad feed rule

Signed attack signatures are fetched from a remote feed. Tampered feeds are rejected.

Unsafe files and MCP tools rule

A pickle scan blocks code execution. MCP tools are pinned by sha256 and changed tools are quarantined.

Budgets and loops rule

USD, tokens, steps and compute seconds, for cloud and local models. Repeated calls are stopped.

Privacy vault rule

Bank and personal data are tokenized before they reach a commercial model.

Live: the agent tried to pay a "reminder" for a bill paid last week. The contract found the earlier payment and held it for a person who is allowed to approve.

Practical implementability and scalability Practicality and scalability 15% of the score

Drop it in front of any agent. Change behaviour by editing a file.

Three ways in

  • Python SDKOne call: gate.call_tool.

  • MCP gatewayWorks with any MCP client.

  • Separate layer processOne per agent.

Three config files

  • policy.yamlLenient, balanced and strict presets, budgets and allowed models.

  • Contracts per toolWhat each risky action is checked against.

  • Signed attack feedKnown attack patterns.

Live changes. Edits apply to the next action within 0.5 s. Invalid edits are rejected with the reason.

New business area means a new contract file, not new code.

Cloud or local. Gemini on Vertex or Ollama on a laptop, with the same checks and budgets for both.

Scales out. Each check is fast and stateless except a small shared state store, so more gate processes means more capacity.
